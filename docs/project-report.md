# 《计算机网络》课程知识图谱项目简短报告

## 1. 项目目标

本项目把分散在教材、课堂讲义、协议标准、实验指导、案例和试题中的课程资源重新标引为可计算的知识图谱，并提供二维/三维可视化和增删改查平台。课程按三篇十章组织，图谱按概念层、案例层和问题层组织，使学生能够从知识点继续查看前置知识、相关协议、典型案例和练习题。

## 2. 资源来源

- 课程主线与术语：谢希仁《计算机网络》教材的章节体系和基本概念。
- 协议语义：IETF RFC 文档，包括 IPv6、TCP、UDP、DNS 和 HTTP 等协议标准。
- 实践方法：Wireshark 官方用户指南、Python Socket Programming HOWTO，以及项目内八个核心篇实验案例。
- 视频资源：参考谢希仁教材体系的公开计算机网络微课堂，链接记录在课程根节点和资源目录中。
- 试题资源：依据知识点描述、协议字段、算法步骤和典型计算场景自主编写，答案和解析与知识点逐项关联。

本项目不复制教材正文或商业题库，知识点描述和试题均采用重新组织与自主表述。

## 3. 标引规则

1. 每个实体使用稳定且唯一的字符串 ID；核心篇统一使用 `core_` 前缀，补充题使用 `project_q_` 前缀。
2. 概念层节点必须包含 ID、名称、类型、章节、描述和关键词；类型限定为协议、概念、技术、算法、设备或服务。
3. 案例层记录背景、步骤、分析和关联知识点；问题层记录题干、题型、选项、答案、解析、难度和主知识点。
4. “包含”从整体指向组成机制；“前置知识”从基础概念指向后续概念；“属于层”从知识点指向章节根节点；“应用于”从原理指向应用；“对比”表达同类技术差异；“依赖”表达运行依赖。
5. 每个概念知识点至少关联三道试题。所有边、试题和案例的引用在生成后进行完整性检查，禁止悬空 ID。

## 4. 图谱 Schema

### Node

```json
{
  "id": "core_ch6_tcp",
  "name": "TCP协议",
  "type": "协议",
  "layer": "概念层",
  "chapter": "传输层",
  "description": "面向连接的可靠传输协议",
  "keywords": ["可靠传输", "拥塞控制", "流量控制"]
}
```

### Edge

```json
{
  "id": "core_edge_0001",
  "source": "core_ch6_tcp",
  "target": "core_ch6_congestion",
  "relation": "包含",
  "description": "TCP包含拥塞控制机制"
}
```

### Case 与 Question

案例通过 `related_nodes` 关联多个知识点；试题同时使用 `knowledge_point_id` 和 `related_nodes`，兼容主知识点查询和多知识点关联。运行时数据保存在 `backend/data`，核心篇独立交付文件保存在 `data/core`。

## 5. 平台功能

- 二维力导向图和三维力导向图展示。
- 按章节、概念/案例/问题层筛选，并支持关键词搜索。
- 点击节点查看属性、相邻关系、关联试题和关联案例。
- 知识点、关系、案例和试题的新增、编辑、删除与查询。
- JSON 数据导入和导出。
- 网络层蓝色、传输层绿色、应用层橙色的核心篇颜色标识。
- 第 5、6、7 章完整子图 API，以及节点关联题和案例 API。

## 6. 当前规模与验证

- 概念知识点：209 个。
- 问题层及关联试题：630 道，每个概念知识点至少 3 道。
- 案例：21 个。
- 核心篇：81 个知识点、243 道题、8 个案例、437 条关系。

项目通过 JSON 解析、ID 唯一性、引用完整性、FastAPI GET/CRUD 冒烟测试、Python 编译、TypeScript 类型检查和 Vite 生产构建。演示截图位于 `docs/demo/screenshots`。

## 7. 后续改进

后续可将 JSON 存储迁移到 Neo4j，增加全文与向量检索、学习路径推荐、随机组卷和答题反馈；前端可按路由懒加载 Three.js 和图谱组件以缩小首屏包体；案例可继续增加 PCAP、Packet Tracer 拓扑和可直接运行的 Socket 示例工程。
